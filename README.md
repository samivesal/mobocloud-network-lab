# MoboHub Network Lab

MoboHub یک پنل مدیریت محلی برای بررسی کانفیگ‌های اشتراک از اینترنت همان دستگاه است. برای نمونه، اگر آن را روی یک سیستم داخل خانه اجرا کنید، می‌توانید ببینید هر کانفیگ از اتصال خانگی قابل استفاده است یا خیر. پنل فارسی است و نتایج در SQLite روی همان دستگاه ذخیره می‌شوند.

## نصب و اجرای پنل روی Debian 13

این یک خط را در ترمینال **سیستم مقصد** اجرا کنید. پیش‌نیازها Debian 13 با systemd، دسترسی sudo، اینترنت و حساب GitHub دارای دسترسی به مخزن خصوصی هستند.

```sh
( set -eu; . /etc/os-release; [ "$ID:$VERSION_ID" = debian:13 ] || { echo "Debian 13 required" >&2; exit 1; }; if ! command -v gh >/dev/null; then sudo apt-get update && sudo apt-get install -y gh; fi; gh auth status --hostname github.com >/dev/null 2>&1 || gh auth login --hostname github.com --web --git-protocol https; work=$(mktemp -d); trap 'rm -rf -- "$work"' EXIT; gh api --hostname github.com repos/samivesal/mobohub-network-lab/tarball/main > "$work/source.tgz"; tar -xzf "$work/source.tgz" --strip-components=1 -C "$work"; sudo "$work/deployment/install" --start )
```

اگر اولین بار است، دستور ورود به GitHub را در مرورگر شروع می‌کند. نصب‌کننده در صورت نیاز Xray را از انتشار رسمی GitHub دریافت می‌کند و پس از بررسی SHA-256 نصب می‌کند. در نصب اول، اگر می‌خواهید تست زندهٔ اشتراک فعال باشد، به پرسش Cloudflare پاسخ `y` بدهید و یک رمز مدیر با حداقل **۱۲ کاراکتر** تعیین کنید. آدرس پیش‌فرض [پنل وب](http://127.0.0.1:8765) است و آدرس واقعی پس از نصب در ترمینال نمایش داده می‌شود. برای دسترسی از دستگاه دیگر می‌توانید از تونل SSH استفاده کنید.

برای دیدن وضعیت سرویس، گزارش‌ها، بازراه‌اندازی یا ویرایش تنظیمات، منوی ترمینال را با `sudo mobohub` باز کنید. تغییر تنظیمات از گزینهٔ «ویرایش تنظیمات» و اعمال آن از گزینهٔ «راه‌اندازی مجدد» انجام می‌شود.

اجرای دوبارهٔ دستور، نسخهٔ برنامه را جایگزین می‌کند و فایل تنظیمات، رمز و کلید موجود و دیتابیس را حفظ می‌کند. اگر دیتابیس وجود داشته باشد ولی فایل هویت پیدا نشود، نصب متوقف می‌شود تا کلید اصلی بازیابی شود.

| مسیر | کاربرد |
|---|---|
| `/etc/mobohub-network-lab/settings` | تنظیمات و مقصدهای تست |
| `/etc/mobohub-network-lab/keys/identity.json` | هش رمز مدیر و کلید رمزنگاری |
| `/var/lib/mobohub-network-lab` | دیتابیس و وضعیت محلی |
| `/opt/mobohub-lab/current` | نسخهٔ فعال برنامه |

نصب‌کننده برای Debian 13 طراحی شده است. نصب کامل روی یک سیستم تازه در این نشست آزموده نشده است.

## اجرای تست اشتراک

نصب اولیه پنل را بالا می‌آورد. اگر در نصب اول تست زنده را فعال کردید، مقصدهای پیش‌فرض Cloudflare آماده‌اند. برای تنظیم دستی تست واقعی، Xray باید در دسترس باشد. در فایل تنظیمات `LAB_LIVE=1`، `LAB_SPEED=1` و `LAB_SCHEDULE=1` را فعال کنید. `LAB_CHECK_URL` و `LAB_DOWNLOAD_URL` باید به مقصدهای HTTPS مورد تأیید شما اشاره کنند. مقصد دانلود باید بدنه‌ای دقیقاً به اندازهٔ `LAB_DOWNLOAD_BYTES` برگرداند. برای آپلود، `LAB_UPLOAD_URL` را روی مقصدی بگذارید که درخواست POST را می‌پذیرد. پس از تغییر تنظیمات، سرویس `mobohub-lab` را بازراه‌اندازی کنید. جزئیات در [راهنمای عملیاتی](docs/operations.md) آمده است.

- لینک HTTPS اشتراک و رابط شبکه را در پنل ثبت کنید. پنل اجرای فوری و دوره‌های ۱۲ و ۲۴ ساعته دارد. می‌توانید اجرای دوره‌ای هر اشتراک را متوقف کنید یا اشتراک را با تأیید حذف کنید. حذف اشتراک، نتایج قبلی را در تاریخچه نگه می‌دارد.
- برای هر کانفیگ، درخواست سنجش از ورودی SOCKS محلی به Xray می‌رسد. Xray با خود کانفیگ به سرور آن وصل می‌شود. اتصال به سرور کانفیگ از رابط انتخاب‌شده می‌گذرد. درخواست پایهٔ مستقیم جداگانه ثبت می‌شود.
- پینگ، دانلود و آپلود جداگانه نمایش داده می‌شوند. پینگ تأخیر پاسخ HTTPS پس از آماده‌شدن اتصال است و با عدد صحیح بر حسب میلی‌ثانیه نمایش داده می‌شود. سرعت‌ها بر حسب Mbps هستند. مقصدهای غیرعمومی پذیرفته نمی‌شوند.
- دکمهٔ «تست فوری Cloudflare» هر سه اندازه‌گیری را از همان کانفیگ به Cloudflare می‌فرستد. پینگ از میانهٔ پاسخ پنج درخواست محاسبه می‌شود. برای دانلود و آپلود، تست از حجم کم شروع می‌کند و اگر انتقال سریع باشد حجم را بیشتر می‌کند. سرعت از میانهٔ انتقال‌های موفق در حجم انتخاب‌شده محاسبه می‌شود و تعداد نمونه‌های موفق کنار هر نتیجه نمایش داده می‌شود. زمان آپلود تا دریافت پاسخ سرور محاسبه می‌شود. پنل عدد آپلود را به‌صورت صحیح نشان می‌دهد و سرعت مثبت زیر ۱ را به‌صورت «کمتر از ۱» نمایش می‌دهد. مهلت هر درخواست پینگ ۳۰ ثانیه و هر انتقال ۶۰ ثانیه است. اجرای دوره‌ای از مقصدهای تنظیم‌شده روی سرور استفاده می‌کند.

## Ookla و تلگرام

**Ookla Speedtest.net** هنوز به پنل وصل نشده است. انتخاب خودکار سرور Ookla و اجرای تست از مسیر هر کانفیگ هنوز در این پروژه پیاده‌سازی و تأیید نشده است. نتایج فعلی از درخواست‌های HTTPS خود MoboHub می‌آیند.

**تلگرام** به‌صورت پیش‌فرض خاموش است. کد ارسال اعلان رخداد و در صورت فعال‌کردن، گزارش‌های دوره‌ای وجود دارد. برای استفاده باید `LAB_TELEGRAM=1`، `LAB_BOT_TOKEN` و `LAB_CHAT_ID` در تنظیمات محلی تعیین شوند. گزارش‌ها به `LAB_SEND_SUMMARIES=1` هم نیاز دارند. در آزمون‌ها ارسال و تلاش مجدد با پاسخ‌های ساختگی بررسی می‌شوند. ارسال زنده در این انتشار تأیید نشده است.

## توسعه

آزمون‌ها را با `python -m unittest discover -v` اجرا کنید. برای آزمون مرورگر و آزمون یکپارچه با Xray به [راهنمای عملیاتی](docs/operations.md) رجوع کنید. فایل `.env.example` الگوی بی‌اعتبارنامهٔ تنظیمات است. لینک اشتراک، کلید، توکن، دیتابیس و نتیجهٔ شخصی را خارج از Git نگه دارید.
